[C-1] SEC-02 — Pas de rate limiting sur /api/auth/login et /api/auth/register
Fichier : back/app.js
────────────────────────────────────────────────────────────────────────────────

PROBLÈME :
  Un attaquant peut envoyer 100 000 tentatives de login par minute par brute-force
  sans aucune résistance. Le site serait compromis en quelques heures.

SOLUTION — Ajouter express-rate-limit AVANT les routes auth :

  Dans back/app.js, après les imports existants, ajouter :

  ┌─────────────────────────────────────────────────────────────────────────────
  │ const rateLimit = require('express-rate-limit');
  │ const helmet = require('helmet');
  │
  │ // Sécurité HTTP headers (OWASP)
  │ app.use(helmet());
  │
  │ // Rate limit strict sur auth (10 tentatives / 15 minutes par IP)
  │ const authLimiter = rateLimit({
  │   windowMs: 15 * 60 * 1000,   // 15 minutes
  │   max: 10,
  │   message: { success: false, message: 'Trop de tentatives. Réessayez dans 15 minutes.' },
  │   standardHeaders: true,
  │   legacyHeaders: false,
  │ });
  │
  │ // Rate limit général sur toute l'API (200 req / min par IP)
  │ const apiLimiter = rateLimit({
  │   windowMs: 60 * 1000,
  │   max: 200,
  │   message: { success: false, message: 'Trop de requêtes. Réessayez dans un instant.' },
  │ });
  │
  │ app.use('/api/auth/login',    authLimiter);
  │ app.use('/api/auth/register', authLimiter);
  │ app.use('/api',               apiLimiter);
  └─────────────────────────────────────────────────────────────────────────────

  Placer ces lignes APRÈS app.use(express.json()) mais AVANT app.use('/api/auth', authRoutes).

POURQUOI CETTE APPROCHE :
  express-rate-limit est maintenu, léger, et fonctionne en production sans Redis
  (en mémoire). Helmet corrige 11 failles HTTP header en une ligne.

[C-2] BUG-01 — Race condition : commande créée AVANT déduction du solde
Fichier : back/routes/orderRoutes.js, lignes 143-159
────────────────────────────────────────────────────────────────────────────────

PROBLÈME ACTUEL :
  1. Order.create() → commande créée
  2. user.save() → si cette ligne échoue (timeout, erreur réseau, crash),
     le client a sa commande MAIS son solde n'a pas été débité.
  Il obtient le service gratuitement.

SOLUTION — Opération atomique avec findOneAndUpdate :
  L'astuce : utiliser $inc avec une condition { balance: { $gte: finalAmount } }.
  MongoDB garantit atomicité au niveau document sans transaction.
  Si le solde est insuffisant au moment de l'opération, rien n'est modifié.

  Remplacer les lignes 111-159 par :

  ┌─────────────────────────────────────────────────────────────────────────────
  │ // 1. Vérifier que le service est actif
  │ const service = await Service.findById(serviceId);
  │ if (!service) return res.status(404).json({ success: false, message: 'Service non trouvé' });
  │ if (!service.active) return res.status(400).json({ success: false, message: 'Ce service est temporairement indisponible' });
  │
  │ // 2. Calculer le montant réel côté serveur (ne jamais faire confiance au client)
  │ let finalAmount = service.price;
  │ let finalQty = 1;
  │ if (quantity && totalPrice) {
  │   const parsedQty = parseInt(quantity, 10);
  │   if (isNaN(parsedQty) || parsedQty < 1) {
  │     return res.status(400).json({ success: false, message: 'Quantité invalide' });
  │   }
  │   finalAmount = service.price * parsedQty;  // ← recalcul serveur, pas confiance au totalPrice client
  │   finalQty = parsedQty;
  │ }
  │
  │ // 3. Déduction atomique : ne débite QUE SI balance >= finalAmount
  │ //    findOneAndUpdate avec condition = opération atomique MongoDB
  │ const updatedUser = await User.findOneAndUpdate(
  │   { _id: userId, balance: { $gte: finalAmount } },   // ← condition atomique
  │   { $inc: { balance: -finalAmount } },                // ← déduction atomique
  │   { new: true }
  │ );
  │ if (!updatedUser) {
  │   // Deux causes possibles : solde insuffisant OU utilisateur inexistant
  │   const userCheck = await User.findById(userId);
  │   if (!userCheck) return res.status(404).json({ success: false, message: 'Utilisateur non trouvé' });
  │   return res.status(400).json({ success: false, message: 'Solde insuffisant' });
  │ }
  │
  │ // 4. Créer la commande. Si ça échoue → on rembourse immédiatement (compensation)
  │ let order;
  │ try {
  │   order = await Order.create({
  │     userId,
  │     serviceId,
  │     serviceDetails: { name: service.name, price: service.price, category: service.category },
  │     userSubmittedData: userSubmittedData || {},
  │     amount: finalAmount,
  │     quantity: finalQty,
  │     status: 'pending',
  │   });
  │ } catch (orderErr) {
  │   // COMPENSATION : rembourser si la création de commande échoue
  │   await User.findByIdAndUpdate(userId, { $inc: { balance: finalAmount } });
  │   console.error('Création commande échouée, solde remboursé:', orderErr);
  │   return res.status(500).json({ success: false, message: 'Erreur lors de la création de la commande. Votre solde a été restauré.' });
  │ }
  │
  │ res.status(201).json({ success: true, data: order, newBalance: updatedUser.balance });
  └─────────────────────────────────────────────────────────────────────────────

POURQUOI CETTE APPROCHE :
  • findOneAndUpdate avec condition = atomique sans replica set MongoDB
  • Si la déduction réussit mais la création de commande échoue → compensation immédiate
  • On ne fait jamais confiance au prix envoyé par le frontend (recalcul serveur)

[C-3] BUG-02 — Double remboursement possible (N1 + N2 concurrent)
Fichier : back/routes/adminRoutes.js, lignes 186-206 et 299-344
────────────────────────────────────────────────────────────────────────────────

PROBLÈME ACTUEL :
  L'annulation (N1) et le remboursement de litige (N2) utilisent :
    order = await Order.findByIdAndUpdate(...)
    client.balance += refundAmount; await client.save();
  Deux admins simultanés peuvent déclencher les deux avant que l'un des
  statuts soit persisté → double crédit de 100% du montant.

SOLUTION — Remplacer par findOneAndUpdate atomique avec garde sur le statut :

  ┌── Pour le remboursement N1 (annulation, lignes 186-206) ───────────────────
  │ // Protection atomique : ne rembourse QUE si le statut est encore annulable
  │ // et n'a PAS déjà été remboursé
  │ if (status === 'Annulé' && orderBefore.status !== 'Annulé') {
  │   const refundAmount = orderBefore.amount || orderBefore.serviceDetails?.price || 0;
  │   if (refundAmount > 0) {
  │     // Atomique : ne crédite QUE si le statut de la commande est maintenant 'Annulé'
  │     // (vérification que personne d'autre n'a changé le statut entre-temps)
  │     const guardedOrder = await Order.findOneAndUpdate(
  │       { _id: orderBefore._id, status: { $nin: ['Annulé', 'Remboursé'] } },
  │       { $set: { status: 'Annulé', cancelledAt: new Date() } },
  │       { new: true }
  │     );
  │     if (guardedOrder) {
  │       // Ce bloc ne s'exécute qu'une SEULE fois même en cas d'appels concurrents
  │       await User.findByIdAndUpdate(
  │         orderBefore.userId,
  │         { $inc: { balance: refundAmount } }
  │       );
  │     }
  │   }
  │ }
  └─────────────────────────────────────────────────────────────────────────────

  ┌── Pour le remboursement N2 (litige, lignes 299-344) ───────────────────────
  │ // Utiliser findOneAndUpdate pour changer le statut ATOMIQUEMENT
  │ // Le filtre { status: { $nin: ['Remboursé', 'Annulé'] } } garantit
  │ // qu'un seul remboursement peut réussir même si deux admins cliquent ensemble
  │ const guardedOrder = await Order.findOneAndUpdate(
  │   {
  │     _id: orderId,
  │     status: { $in: ['Terminé', 'completed'] }  // seules ces commandes sont remboursables
  │   },
  │   {
  │     $set: {
  │       status: 'Remboursé',
  │       refundReason: refundReason || 'Litige technique',
  │       refundedAt: new Date(),
  │       refundedBy: req.user.id
  │     }
  │   },
  │   { new: true }
  │ );
  │ if (!guardedOrder) {
  │   return res.status(409).json({
  │     success: false,
  │     message: 'Cette commande a déjà été remboursée ou ne peut pas l\'être.'
  │   });
  │ }
  │ // Si on arrive ici, on est le seul à avoir modifié le statut
  │ await User.findByIdAndUpdate(order.userId, { $inc: { balance: refundAmount } });
  └─────────────────────────────────────────────────────────────────────────────

POURQUOI CETTE APPROCHE :
  findOneAndUpdate avec une condition de filtre sur le statut = verrou optimiste.
  Si deux admins cliquent simultanément, le second findOneAndUpdate ne trouvera
  plus le document (statut déjà modifié par le premier) et retournera null.
  Un seul remboursement passe. Pas besoin de Redis ou de mutex.

[M-13] COH-07 — JWT 30 jours sans refresh token ni révocation
Fichier : back/controllers/authController.js
────────────────────────────────────────────────────────────────────────────────

SOLUTION — Implémenter un refresh token :

  ┌── Principe ─────────────────────────────────────────────────────────────────
  │ • Access token : courte durée (15 min → 1h)
  │ • Refresh token : longue durée (7 jours), stocké en base
  │ • Si access token expire → client envoie refresh token → nouveau access token
  └─────────────────────────────────────────────────────────────────────────────

  ┌── back/controllers/authController.js — générer les deux tokens ─────────────
  │ const crypto = require('crypto');
  │
  │ const generateAccessToken = (id, role, email, name, isMaintenanceAllowed) => {
  │   return jwt.sign(
  │     { id, _id: id, role, email, name, isMaintenanceAllowed },
  │     process.env.JWT_SECRET,
  │     { expiresIn: '1h' }    // ← réduit de 30d à 1h
  │   );
  │ };
  │
  │ const generateRefreshToken = () => crypto.randomBytes(64).toString('hex');
  │
  │ // Dans login() :
  │ const accessToken  = generateAccessToken(user._id, user.role, user.email, user.name, user.isMaintenanceAllowed);
  │ const refreshToken = generateRefreshToken();
  │ const refreshExpiry = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000); // 7 jours
  │
  │ // Stocker le refresh token en base (hasher pour la sécurité)
  │ user.refreshToken       = crypto.createHash('sha256').update(refreshToken).digest('hex');
  │ user.refreshTokenExpiry = refreshExpiry;
  │ await user.save();
  │
  │ res.json({ ..., token: accessToken, refreshToken });
  └─────────────────────────────────────────────────────────────────────────────

  ┌── back/routes/authRoutes.js — route de refresh ─────────────────────────────
  │ router.post('/refresh', async (req, res) => {
  │   const { refreshToken } = req.body;
  │   if (!refreshToken) return res.status(401).json({ message: 'Token manquant' });
  │
  │   const hashed = crypto.createHash('sha256').update(refreshToken).digest('hex');
  │   const user = await User.findOne({
  │     refreshToken: hashed,
  │     refreshTokenExpiry: { $gt: new Date() }
  │   });
  │   if (!user) return res.status(401).json({ message: 'Session expirée, reconnectez-vous' });
  │
  │   const newAccess = generateAccessToken(user._id, user.role, user.email, user.name, user.isMaintenanceAllowed);
  │   res.json({ token: newAccess });
  │ });
  └─────────────────────────────────────────────────────────────────────────────

  ┌── Ajouter dans le modèle User ──────────────────────────────────────────────
  │ refreshToken:       { type: String, default: null },
  │ refreshTokenExpiry: { type: Date,   default: null },
  └─────────────────────────────────────────────────────────────────────────────

  ┌── front/src/services/api.js — intercepteur pour auto-refresh ───────────────
  │ api.interceptors.response.use(
  │   r => r,
  │   async err => {
  │     if (err.response?.status === 401 && !err.config._retry) {
  │       err.config._retry = true;
  │       const rt = localStorage.getItem('refreshToken');
  │       if (rt) {
  │         try {
  │           const { data } = await axios.post('/api/auth/refresh', { refreshToken: rt });
  │           localStorage.setItem('token', data.token);
  │           err.config.headers.Authorization = `Bearer ${data.token}`;
  │           return api(err.config);
  │         } catch { localStorage.clear(); window.location.href = '/login'; }
  │       }
  │     }
  │     return Promise.reject(err.response?.data || err);
  │   }
  │ );
